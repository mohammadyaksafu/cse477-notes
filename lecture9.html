    Generator (Primitive root) ও Discrete Logarithm

    Zp-এ সব হিসাব mod p (p prime)। g-কে generator / primitive root বলে যদি g-এর power গুলো Zp-এর সব nonzero মান একবার করে তৈরি করে।

    3 mod 7 এর power: 3⁰=1, 3¹=3, 3²=2, 3³=6, 3⁴=4, 3⁵=5, 3⁶=1 → {1,3,2,6,4,5} সব! ✅ 3 is a generator of Z7 3 mod 11 এর power: 1, 3, 9, 5, 4, 1 … → শুধু {1,3,9,5,4}, পুনরাবৃত্তি ❌ 3 is NOT a generator of Z11
    • Zp-তে generator আছে Φ(p−1) টা — তাই কয়েকটা চেষ্টা করলেই পাওয়া যায়।
    • g থাকলে x = gk mod p সহজেই হিসাব করা যায় (repeated squaring)।
    • কিন্তু উল্টোটা — x, g, p দিয়ে k বের করা — হলো discrete logarithm problem, যা factoring-এর মতোই কঠিন বলে বিশ্বাস করা হয়।
    📖 গল্প

    রঙ মেশানো: হলুদ রঙে g বার নীল ফোঁটা দেওয়া সহজ (power)। কিন্তু চূড়ান্ত সবুজ রঙ দেখে বলা — কত ফোঁটা দেওয়া হয়েছিল — প্রায় অসম্ভব (discrete log)।

    🧪 Generator checker

    Elgamal Cryptosystem — randomized public key

    Taher Elgamal-এর আবিষ্কার। Randomization ব্যবহার করে — একই plaintext বারবার encrypt করলে প্রতিবার ভিন্ন ciphertext (RSA-র determinism সমস্যার সমাধান!)।

    Setup (Bob): বড় র‍্যান্ডম prime p, generator g বেছে নেয়। র‍্যান্ডম x (1 থেকে p−2) নিয়ে হিসাব: y = gx mod p

    Secret key = x; Public key = (p, g, y)

    Encryption (Alice): Bob-এর public key (p, g, y) নেয়, র‍্যান্ডম k (1 থেকে p−2) বাছে:

    a = gk mod p b = M · yk mod p Ciphertext = (a, b)

    Decryption (Bob):

    M = b · (ax)−1 mod p

    Correctness:

    b·(ax)−1 = M·yk·(gk)−x = M·gxk·g−kx = M ✅

    Bob-এর k জানার দরকার নেই, Alice-এর x জানার দরকার নেই। দুজনে অজান্তেই একটা one-time shared key gxk হিসাব করেছে — Alice yk দিয়ে, Bob ax দিয়ে।

    Security: x না জেনে (a, b) decrypt কঠিন; y = gx পাবলিক, তাই x বের করা = discrete log সমাধান।

    সতর্কতা: প্রতিটা বার্তায় নতুন k। k পুনরায় ব্যবহার করলে one-time pad পুনর্ব্যবহারের মতো তথ্য ফাঁস হবে।

    🧪 Elgamal playground

    বারবার Encrypt চাপো — একই M-এর ciphertext প্রতিবার আলাদা, কিন্তু decrypt সবসময় একই M দেয়।

    Key Exchange ও Diffie-Hellman

    Symmetric crypto-র আগে Alice-Bob-কে একটা গোপন key-তে একমত হতে হয়। পুরনো উপায়: একবার সরাসরি গোপনে দেখা, বা tamper-proof খামে পাঠানো। Key exchange (key agreement) protocol: আগের কোনো গোপন যোগাযোগ ছাড়াই শুধু insecure channel দিয়ে shared secret তৈরি।

    ⚠️ গুরুত্বপূর্ণ তত্ত্ব

    Adversary যদি বার্তা actively বদলাতে পারে তাহলে কোনো key exchange protocol সম্ভব নয় (authentication ছাড়া)। কিন্তু adversary শুধু passive eavesdropping করলে সম্ভব।

    Diffie-Hellman (Whitfield Diffie ও Martin Hellman)

    পাবলিক প্যারামিটার (attacker-সহ সবাই জানে): prime p ও generator g।

    নিরাপত্তা: X ও Y দেখে K বের করা কঠিন — x বা y উদ্ধার করা = discrete log।

    📖 রঙের গল্প (বিখ্যাত ব্যাখ্যা)

    দুজনে প্রকাশ্যে একটা সাধারণ রঙ ঠিক করল — হলুদ (g)। Alice গোপনে লাল মেশাল, Bob গোপনে নীল। মিশ্র রঙ দুটো তারা প্রকাশ্যে বিনিময় করল। এবার প্রত্যেকে অন্যের মিশ্রণে নিজের গোপন রঙ মেশাল → দুজনেরই হলুদ+লাল+নীল = একই বাদামি! Eve দুটো মিশ্র রঙ দেখেছে, কিন্তু রঙ “আলাদা” করতে পারে না।

    🧪 DH Playground — Mallory চালু/বন্ধ করো

    DH-এর উপর MITM আক্রমণ

    Passive attacker-এর বিরুদ্ধে নিরাপদ, কিন্তু Mallory বার্তা আটকে বদলাতে পারলে: সে নিজের s, t বাছে; Alice-কে পাঠায় S = gs, Bob-কে T = gt। ফলে Alice-Mallory-র key K1 = gxs, Mallory-Bob-এর key K2 = gyt। Mallory K1 দিয়ে decrypt করে পড়ে, K2 দিয়ে encrypt করে Bob-কে পাঠায় — কেউ টের পায় না! সমাধান: authentication (signature/certificate)।

    Cryptographic Hash Function — গুণ ও গঠন

    বার্তার একটা compressed digest, তিনটা গুণসহ: deterministic, one-way, collision-resistant।

    • Deterministic: একই ইনপুট → সবসময় একই আউটপুট।
    • Hash মান বার্তার চেয়ে অনেক ছোট (SHA-256 → 256 bit)।
    • ইনপুটের এক bit বদলালে আউটপুটের প্রতিটা bit প্রভাবিত হতে পারে (diffusion) — substitution, permutation, XOR, iteration ব্যবহার করে।
    • One-way: M থেকে H(M) সহজ; x দেখে এমন M খোঁজা যাতে H(M) = x — কঠিন।

    নির্দিষ্ট একটা M দেওয়া আছে — এমন M′ ≠ M খোঁজা কঠিন যেখানে H(M′) = H(M)।

    Merkle–Damgård construction

    ভিত্তি একটা compression function C(X, Y): X-এর দৈর্ঘ্য m, Y-এর দৈর্ঘ্য n, আউটপুট n bit।

    IV (v)→ C(M1, v) = d1 →d1→ C(M2, d1) = d2 →…→ C(Mk, dk−1) →H = dk

    M-কে m-bit block M1…Mk-তে ভাগ করো (শেষটা দ্ব্যর্থহীনভাবে pad)। Ralph Merkle ও Ivan Damgård-এর নামে।

    Birthday Attack

    Hash-কে আক্রমণের প্রধান উপায় collision resistance ভাঙা — cryptanalysis দিয়ে, অথবা brute-force birthday attack দিয়ে। পরিসংখ্যানের এক অবিশ্বাস্য সত্য: 23 জনের বেশি হলে দুজনের জন্মদিন মেলার সম্ভাবনা 50%-এর বেশি; 60+ হলে প্রায় নিশ্চিত।

    P(A) = অন্তত দুজনের জন্মদিন এক — সরাসরি হিসাব কঠিন। তার বদলে P(A′) = কারোরই এক নয়। P(A) = 1 − P(A′)।

    প্রথম ব্যক্তি: 365/365। দ্বিতীয়: 364/365 (প্রথমজনের থেকে আলাদা)। তৃতীয়: 363/365…

    P(A′) = 365/365 × 364/365 × … × 343/365 = (1/365²³)·(365×364×…×343) = 0.492703 P(A) = 1 − 0.492703 = 0.507297 ≈ 50.7% > 50%

    Hash-এ প্রয়োগ: n-bit hash-এ collision পেতে 2n নয়, মাত্র প্রায় 2n/2 টা র‍্যান্ডম বার্তা লাগে। তাই 128-bit MD5 আসলে ~264 নিরাপত্তা দেয়, আর SHA-256 দেয় ~2128।

    Digital Signature ও RSA Signature

    Digital signature হলো কোনো entity-র পরিচয়কে বার্তার সাথে বেঁধে দিয়ে authenticity প্রমাণের উপায়। Alice private key দিয়ে SAlice(M) বানায়; Bob Alice-এর public key, M ও সই দিয়ে যাচাই করে।

    তিনটা কাঙ্ক্ষিত গুণ

    RSA signature

    Encryption: C = Me mod n (public key দিয়ে) Signature : S = Md mod n (private key d দিয়ে) Verify : M =? Se mod n কারণ : Se = Mde = MkΦ(n)+1 = M·(MΦ(n))k = M (mod n)
    • Nonforgeability: d ছাড়া Md mod n বানানো = RSA ভাঙা।
    • কিন্তু nonmutability নেই! নিচে দেখো।
    🧪 RSA signature mutability আক্রমণ (n = 119, e = 5, d = 77)

    সমাধান: Hash + Signature

    • লম্বা বার্তায় সরাসরি RSA সই অদক্ষ।
    • পুরনো সই গুণ করে নতুন বৈধ সই বানানো যায় (উপরে দেখলে)।
    • তাই বাস্তবে সই করা হয় H(M)-এ — H(M)·H(N) প্রায় কখনোই H(M·N)-এর সমান হবে না, তাই mutability ঝুঁকি অনেক কমে, আর ছোট hash-এ সই দ্রুতও।

    📚 Self Reading (স্লাইড থেকে) — সংক্ষিপ্ত ইঙ্গিতসহ
    TLS handshake-এ hashing, signature ও certificate কীভাবে একসাথে কাজ করে?

    Server তার certificate পাঠায় (CA-র সই করা)। Client ব্রাউজারে থাকা CA public key দিয়ে সই যাচাই করে — সই আসলে certificate-এর hash-এর উপর। তারপর key exchange (যেমন ECDHE) — server তার DH মানে সই করে প্রমাণ দেয় যে সে-ই certificate-এর মালিক (MITM ঠেকায়)। শেষে handshake-এর সব বার্তার hash দিয়ে “Finished” বার্তা — কেউ মাঝখানে কিছু বদলায়নি তা নিশ্চিত।

    HTTPS request → TLS handshake → certificate verification → key exchange: প্রতিটা ধাপ কী নিরাপত্তা যোগ করে?

    Request: কোন সাইট চাই। Handshake: অ্যালগরিদমে একমত। Certificate verification: authenticity (সত্যিই bank.com)। Key exchange: confidentiality-র জন্য shared session key। এরপর symmetric encryption + MAC: confidentiality ও integrity।

    কেন আগে asymmetric, পরে symmetric?

    Asymmetric দিয়ে অপরিচিত দুই পক্ষ নিরাপদে key বিনিময় ও পরিচয় যাচাই করতে পারে, কিন্তু ধীর। Symmetric (AES) অনেক দ্রুত — বিশাল ডেটার জন্য উপযুক্ত। Hybrid = দুটোর সুবিধা (Lecture 4 ও 8)।

    TLS-এর hash ভেঙে গেলে (collision সহজ) কী হারাবে?

    Signature hash-এর উপর হয়, তাই collision পেলে attacker একই hash-ওয়ালা জাল certificate বানাতে পারে (MD5 দিয়ে ২০০৮-এ জাল CA certificate বানানো হয়েছিল) → authenticity ভাঙে, MITM সম্ভব। Handshake/MAC-এর integrity-ও দুর্বল হয়। এনক্রিপশন শক্ত থাকলেও লাভ নেই — কারণ তুমি হয়তো ভুল পক্ষের সাথে নিরাপদে কথা বলছ!
