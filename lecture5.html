    Hash, MAC, Certificate ও Password

    Lecture 4-এর digital signature-এর সমস্যা (সই বার্তার সমান লম্বা, MITM) কীভাবে hash দিয়ে সমাধান হয়; তারপর MAC, digital certificate, আর মানুষের দুর্বলতম জায়গা — password ও social engineering।

    Cryptographic Hash Function

    Hash function হলো বার্তার একটা checksum (ছোট “আঙুলের ছাপ”), সাথে কিছু বিশেষ গুণ:

    • One-way: Y = H(M) বের করা সহজ, কিন্তু শুধু Y দেখে M বের করা কঠিন।
    • Collision-resistant: এমন দুটো বার্তা M ও N খুঁজে পাওয়া কঠিন যেখানে H(M) = H(N)।
    • উদাহরণ: SHA-1, SHA-256।
    📖 গল্প

    মানুষের আঙুলের ছাপ: মানুষ থেকে ছাপ নেওয়া সহজ, কিন্তু ছাপ দেখে পুরো মানুষটা বানানো অসম্ভব (one-way)। আর দুজন মানুষের হুবহু এক ছাপ পাওয়া প্রায় অসম্ভব (collision-resistant)।

    🧪 Live SHA-256 — Avalanche effect দেখো

    মাত্র একটা অক্ষর বদলালে hash-এর প্রায় অর্ধেক bit বদলে যায়। ইনপুট যত বড়ই হোক, আউটপুট সবসময় 256 bit।

    Hash-এর প্রয়োগ: Hash-then-sign ও File integrity

    ১. বার্তার digest-এ সই

    Bob প্রথমে বার্তার hash বানায়: h(M)

    তারপর শুধু hash-টায় সই করে: S = ESB(h(M)) — একে বলে M-এর digest-এ সই।

    Bob পাঠায় (M, S) → Alice।

    Alice নিজে হিসাব করে h′ = h(M), আর সই খুলে পায় h = DPB(S)। যদি h′ = h → বৈধ ✅।

    লাভ: সই ছোট ও দ্রুত (hash ছোট)। MITM থেকেও রক্ষা:

    • Private key ছাড়া attacker বার্তা-সই জোড়া জাল করতে পারবে না → authenticity
    • Collision-resistance-এর কারণে একই digest-ওয়ালা অন্য M′ খুঁজে পাবে না → integrity

    ২. OS-এর গুরুত্বপূর্ণ ফাইলের integrity

    1. প্রতিটা গুরুত্বপূর্ণ ফাইলের hash protected memory-তে রাখো।
    2. Run-time-এ ফাইলের hash আবার হিসাব করো।
    3. দুটো মিলাও — মিললে ফাইল বদলায়নি (collision-resistance)।
    💡 বাস্তবে

    সফটওয়্যার ডাউনলোড পেজে “SHA-256 checksum” দেওয়া থাকে — ডাউনলোডের পর মিলিয়ে নিলে বোঝা যায় কেউ ফাইলে ভাইরাস ঢোকায়নি। Linux-এর Tripwire/AIDE টুলও এটাই করে।

    Message Authentication Code (MAC)

    Hash function + দুই পক্ষের shared secret key K = insecure channel-এ integrity সুরক্ষা, অনেকটা digital signature-এর মতো।

    A = h(K ‖ M) ‖ = concatenation (জোড়া লাগানো)
    1. Alice হিসাব করে A = h(K‖M) — এটাই MAC।
    2. পাঠায় (M, A)।
    3. Bob পায় (M′, A)। নিজে হিসাব করে A′ = h(K‖M′)।
    4. A = A′ হলে Bob নিশ্চিত: বার্তা Alice-এর পাঠানো (authenticity) এবং পথে বদলায়নি (integrity)।

    Digital Certificate ও Certificate Authority

    Public-key crypto shared key-এর সমস্যা মেটায়, কিন্তু একটা ফাঁক থেকে যায়: Alice কীভাবে জানবে যে PB সত্যিই Bob-এর public key? অনেক Bob থাকলে সঠিকজন কোনটা?

    📖 গল্প

    ফেসবুকে “Bob Official” নামে একটা আইডি তোমাকে তার public key পাঠাল। আসলে এটা Mallory-র ফেক আইডি! তুমি সেই key দিয়ে encrypt করলে Mallory পড়ে ফেলবে। সমাধান? জাতীয় পরিচয়পত্র-এর মতো কিছু — যেটা একটা বিশ্বস্ত কর্তৃপক্ষ (নির্বাচন কমিশন) সই করে দেয়।

    সমাধান: একটা বিশ্বস্ত কর্তৃপক্ষ user-এর পরিচয় যাচাই করে, তারপর পরিচয় + public key একসাথে করে digitally sign করে। যেমন:

    💡 স্লাইডের নমুনা

    “The Bob who lives on 11 Main Street in Gotham City was born on August 4, 1981, and has email address bob@gotham.com, has the public key PB, and I stand by this certification until December 31, 2011.”

    • এই বিবৃতি = digital certificate; বিশ্বস্ত কর্তৃপক্ষ = Certificate Authority (CA)।
    • Certificate শক্ত প্রমাণ, তাই unsigned ইমেইল বা third-party সাইট থেকে এলেও Alice বিশ্বাস করতে পারে।
    • কিন্তু CA-র public key-ও বিশ্বাস করতে হবে → circular problem!
    • সমাধান: CA-দের public key OS/Browser-এ আগে থেকেই embed করা থাকে।
    Root CA (ব্রাউজারে বিল্ট-ইন)→ সই করে →bob.com-এর certificate (নাম + PB)→ Alice যাচাই →PB বিশ্বাসযোগ্য ✅
    💡 নিজে দেখো

    ব্রাউজারে যেকোনো HTTPS সাইটের ঠিকানার পাশে 🔒 আইকনে ক্লিক করো → “Certificate” — issuer, valid until, public key সব দেখা যাবে।

    Password — “something you know”

    Password হলো ছোট অক্ষরের ক্রম যা দিয়ে কেউ তার জানা গোপন কিছুর মাধ্যমে নিজেকে authenticate করে। আদর্শ password মনে রাখা সহজ, অনুমান করা কঠিন — কিন্তু এ দুটো লক্ষ্য পরস্পরবিরোধী!

    • মনে রাখা সহজ password → অনুমান করাও সহজ।
    • কঠিন র‍্যান্ডম password → মুখস্থ করা কঠিন।
    💡 স্লাইডের কৌশল — বাক্য থেকে password

    “Mark took Lisa to Disneyland on March 15” → MtLtDoM15 → আরও নিরাপদ: MtL+DoM15

    বাংলায়: “আমি সাস্টে ২০২২ সালে ভর্তি হই!” → AS2022vH!

    Strong password-এ থাকে: UPPER/lower case, special character, সংখ্যা — কমপক্ষে ৩টা গ্রুপ থেকে। স্লাইডের উদাহরণগুলো বিচার করো: Seattle1, M1ke03, P@$$w0rd, TD2k5secV — নিচের টুলে বসিয়ে দেখো!

    একটা বানানো গল্প বলে admin/operator-কে দিয়ে গোপন তথ্য বের করা।

    Security Usability

    একটা নিরাপদ সিস্টেমকে অবশ্যই ব্যবহারযোগ্য হতে হবে — কারণ user-এর কাছে security প্রায়ই দ্বিতীয় লক্ষ্য (সে আসলে ইমেইল পাঠাতে চায়, এনক্রিপ্ট করতে না)।

    Security usability: security গবেষক, মনোবিজ্ঞানী ও কম্পিউটার ইঞ্জিনিয়ারদের মিলিত ক্ষেত্র।

    রিভিশন কুইজ

    ১) Hash-এর digest-এ সই করলে integrity নিশ্চিত হয় কোন গুণের জন্য?
    একই digest-ওয়ালা অন্য বার্তা পাওয়া যায় না।

    দুজনের কাছেই একই key, তাই কে MAC বানিয়েছে তৃতীয় পক্ষের কাছে প্রমাণ করা যায় না।
    ৩) Certificate-এর “circular problem” কী?
    সমাধান: CA public key OS/browser-এ আগে থেকে রাখা।
