    চরিত্র পরিচিতি — ক্রিপ্টোগ্রাফির “নাটক”

    ক্রিপ্টোগ্রাফির সব বইয়ে একই চরিত্ররা অভিনয় করে। এদের চিনে রাখলে বাকি সব লেকচার সহজ হবে:

    👩 Aliceবার্তা পাঠায় (সাধারণত)।
    👨 Bobবার্তা গ্রহণ করে।
    🕵️ EveEavesdropper — শুধু আড়ি পাতে (passive)।
    😈 Mallory / Charlieমাঝখানে বসে বার্তা বদলায় (active, MITM)।
    📖 গল্প

    Alice সিলেটে, Bob ঢাকায়। তারা ইন্টারনেটে (insecure channel) প্রেমপত্র পাঠায়। মাঝখানে পাবলিক Wi-Fi-র মালিক Eve সব প্যাকেট দেখতে পারে। প্রশ্ন: এমনভাবে কীভাবে লিখবে যাতে Eve দেখেও কিছু বুঝতে না পারে? — এটাই encryption-এর উদ্দেশ্য।

    Encryption ও Decryption

    Encryption হলো দুই পক্ষের (Alice ও Bob) মধ্যে insecure channel-এর উপর দিয়ে গোপন যোগাযোগ স্থাপনের উপায় — যেখানে আড়ি পাতা সম্ভব।

    Plaintext M→ E (encrypt) →Ciphertext C→ insecure channel →C→ D (decrypt) →M
    C = E(M) M = D(C)
    • Plaintext (M): আসল বার্তা। Ciphertext (C): এনক্রিপ্টেড রূপ।
    • Alice ও Bob ছাড়া কারো পক্ষে C থেকে M বের করা infeasible হতে হবে — তাই C insecure channel-এ পাঠানো যায়।
    • Decryption-এ একটা গোপন তথ্য লাগে — decryption key। অ্যালগরিদম নিজে পাবলিক সফটওয়্যার হতে পারে, শুধু key গোপন (মনে আছে? Open design!)।
    • Encryption-এও একটা encryption key লাগে যা decryption key-র সাথে সম্পর্কিত। Encryption key থেকে decryption key বের করা যদি সহজ হয়, তাহলে encryption key-ও গোপন রাখতে হবে (→ symmetric)।

    Caesar Cipher — প্রথম cryptosystem

    প্রতিটা অক্ষরকে বর্ণমালায় তিন ঘর পরের অক্ষর দিয়ে বদলাও। এটা একটা shift cipher। সূত্র: s(c, k) — c একটা অক্ষর, k হলো key। k > 0 হলে forward shift (encryption), k < 0 হলে backward shift (decryption)। শেষে পৌঁছালে modulo দিয়ে আবার শুরুতে ঘুরে আসে।

    s(A, 3) = D s(D, −3) = A s(Y, 3) = B (wrap-around)

    নোট: স্লাইডে প্রাচীন ল্যাটিন বর্ণমালার ২৩ অক্ষরের কথা বলা আছে; আমরা আধুনিক ২৬ অক্ষর দিয়ে খেলব।

    Symmetric বনাম Public-key: কতগুলো key লাগে?

    Symmetric cryptosystem দ্রুত ও দক্ষ, কিন্তু মূল সমস্যা key distribution: প্রতিটা জোড়ার আলাদা গোপন key লাগে।

    n জন মানুষ → n(n − 1) / 2 টা key
    📖 গল্প

    ক্লাসে ৬০ জন, প্রত্যেকে প্রত্যেকের সাথে গোপনে কথা বলতে চায় → ৬০×৫৯/২ = ১৭৭০টা আলাদা চাবি! আর প্রতিটা চাবি আগে গোপনে হাতে হাতে পৌঁছাতে হবে। 😩

    প্রতিটা user-এর একটা key pair: public key (P) সবাইকে দাও, private/secret key (S) নিজের কাছে। যে কেউ Bob-এর public key দিয়ে encrypt করতে পারে, কিন্তু শুধু Bob তার private key দিয়ে decrypt করতে পারে।

    n জন মানুষ → প্রত্যেক recipient-এর জন্য মাত্র ১টা public key distribute করতে হয় (মোট n টা key pair)
    📖 গল্প

    Bob তার বাড়ির সামনে একটা খোলা তালার স্তূপ রাখল (public key)। যে কেউ একটা তালা নিয়ে বাক্সে লাগিয়ে পাঠাতে পারে, কিন্তু খোলার চাবি (private key) শুধু Bob-এর কাছে।

    Public-key-এর সমস্যা: symmetric-এর চেয়ে অনেক ধীর, interactive সেশনের জন্য অনুপযুক্ত, আর key অনেক বড় — RSA সাধারণত 2,048-bit, AES সাধারণত 256-bit।

    সমাধান: public-key শুধু একবার ব্যবহার করে একটা shared secret key বিনিময় করো, তারপর বাকি সব কথা symmetric দিয়ে।

    Alice বানায় র‍্যান্ডম key K→EPB(K)→ Bob decrypt →দুজনের কাছে K→AESK(সব বার্তা)
    💡 বাস্তবে

    HTTPS/TLS ঠিক এটাই করে — শুরুতে public-key (handshake), তারপর AES দিয়ে ওয়েবপেজ।

    Digital Signature (মূল ধারণা)

    Public-key সিস্টেমে encryption ও decryption-এর ক্রম উল্টানো যায়:

    EPB( DSB(M) ) = M

    ধাপ ১ — সই করা: Alice তার private key SA দিয়ে M-কে “decrypt” করে: C = DSA(M)। এই C-ই সই।

    ধাপ ২ — পাঠানো: Alice পাঠায় (M, C)।

    ধাপ ৩ — যাচাই: যে কেউ Alice-এর public key PA দিয়ে encrypt করে: M′ = EPA(C)। যদি M = M′ হয় → সই বৈধ ✅।

    কেন কাজ করে? SA শুধু Alice-এর কাছে আছে, তাই এমন C আর কেউ বানাতে পারবে না যাতে EPA(C) = M হয়।

    অসুবিধা: সই বার্তার সমান লম্বা! (বাস্তব জীবনের সই তো ছোট একটা দাগ।) → সমাধান Lecture 5-এ hash দিয়ে।

    📖 গল্প

    প্রিন্সিপালের সিলমোহর শুধু তাঁর ড্রয়ারে থাকে (private key), কিন্তু সিলটা দেখতে কেমন তা সবাই জানে (public key)। তাই যে কেউ যাচাই করতে পারে কাগজটা আসল কি না, কিন্তু নকল বানাতে পারে না।

    Man-in-the-Middle (MITM) Attack

    Charlie (Mallory) Alice আর Bob-এর মাঝখানে বসে আছে। সে পারে: ট্রাফিক দেখতে, বদলাতে, যোগ করতে, মুছে দিতে।

    Charlie কে হতে পারে? ISP, VPN provider, কফিশপের Wi-Fi provider, connection re-route করা attacker, এমনকি অদক্ষ admin।

    ⚠️ মূল কথা

    শুধু ciphertext পাঠানো confidentiality দেয়, কিন্তু authenticity ও integrity দেয় না — attacker ciphertext আটকে বদলে দিতে পারে। Bob কীভাবে নিশ্চিত হবে যে বার্তাটা আসলেই উদ্দিষ্ট বার্তা?

    Signature-এর উপর MITM

    Bob (M, S) → Eve (M′, S′) → Alice ??
    • Eve সই S-কে বদলে S′ করে। Alice যখন S′ যাচাই করে (Bob-এর public key দিয়ে encrypt করে) — পায় M′ (আসল M নয়)।
    • Alice ভাবে Bob M′-এ সই করেছে!
    • কিন্তু Eve ফলাফল বেছে নিতে পারে না (decrypt করার ক্ষমতা নেই) — তাই এই আক্রমণ কাজ করে শুধু যখন যেকোনো bit sequence-ই একটা বৈধ বার্তা।
    • যেমন: public-key দিয়ে একটা র‍্যান্ডম symmetric key পাঠানো হলে — বদলানো key-টাও “বৈধ” দেখায়!
    📖 গল্প

    ডাকপিয়ন খাম খুলে চিঠির অক্ষরগুলো এলোমেলো করে দিল। চিঠিটা বাংলায় হলে প্রাপক বুঝবে “এটা গোলমাল” (অর্থহীন)। কিন্তু চিঠিতে যদি শুধু একটা র‍্যান্ডম লকার নম্বর থাকে — বদলানো নম্বরও দেখতে স্বাভাবিক, প্রাপক টেরই পাবে না।

    Brute-force Attack ও Unicity Distance

    Encryption/decryption function পাবলিক, শুধু key গোপন — তাহলে সব সম্ভাব্য key দিয়ে চেষ্টা করলে? এটাই brute force।

    • Plaintext যদি র‍্যান্ডম binary হয় → attacker বুঝবে না কোনটা সঠিক, আক্রমণ ব্যর্থ।
    • Plaintext যদি প্রাকৃতিক ভাষা হয় → অল্প কয়েকটা (আদর্শভাবে একটা) ফলাফলই অর্থবহ হবে।
    • NGGNPXNGQNJABAVEIVARORNPU → বাতিল। ATTACKATDAWNONIRVINEBEACH → পেয়ে গেছি! 🎯
    🧪 Caesar-কে brute force করো

    যে লাইনে সবচেয়ে বেশি সাধারণ ইংরেজি অক্ষর (E,T,A,O…) সেটা হাইলাইট করা হয় — attacker-ও এভাবেই “অর্থবহ” টেক্সট চেনে।

    গণিতটা ধাপে ধাপে

    ইংরেজি টেক্সট 8-bit ASCII-তে। t অক্ষরের বার্তা = n = 8t bit।

    সম্ভাব্য n-bit array মোট 28t = 2n।

    ইংরেজির প্রতিটা অক্ষর গড়ে মাত্র ≈1.25 bit তথ্য বহন করে (= entropy of English)।

    অর্থবহ ইংরেজি t-byte array-এর সংখ্যা: 21.25t = 21.25n/8 ≈ 20.16n

    সাধারণভাবে কোনো ধ্রুবক 0 < α < 1-এর জন্য 2n-এর মধ্যে মাত্র 2αn বৈধ বার্তা।

    র‍্যান্ডম plaintext অর্থবহ হওয়ার সম্ভাবনা: 2αn/2n = 1/2(1−α)n — n বাড়লে দ্রুত শূন্যের দিকে যায়।

    Key-র দৈর্ঘ্য k bit → একটা ciphertext-এর জন্য 2kটা সম্ভাব্য plaintext।

    এদের মধ্যে প্রত্যাশিত বৈধ বার্তার সংখ্যা: 2k / 2(1−α)n

    এই সংখ্যা যখন ≈ 1, তখন অনন্য বৈধ plaintext পাওয়া যায়:

    n = k / (1 − α) ← Unicity distance

    সংজ্ঞা: ciphertext-এর ন্যূনতম যত অক্ষর লাগে যাতে মাত্র একটা অর্থবহ plaintext থাকে।

    AES-256 + English: k = 256, α ≈ 0.16 → n ≈ 256/0.84 ≈ 304 bit ≈ 38 ASCII অক্ষর — মাত্র আধা লাইন!

    সিদ্ধান্ত: খুব ছোট না হলে প্রাকৃতিক ভাষার বার্তায় brute force “সঠিক উত্তর চিনতে” পারবে। (তবে 2256 key চেষ্টা করাই অসম্ভব — তাই key লম্বা ও র‍্যান্ডম হতে হবে।)

    ছোট বার্তার উদাহরণ: FJKFPO (substitution cipher) brute force করলে আসতে পারে: thatis, ofyour, season, onyour, thatwe, thetop, thetwo, oxford, thatin, thatof… কোনটা সঠিক? জানা অসম্ভব! — কারণ বার্তাটা unicity distance-এর চেয়ে ছোট।
